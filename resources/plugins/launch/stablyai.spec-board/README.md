# OpenSpec × Superpowers 看板

把 OpenSpec 的规格变更和 Superpowers 的设计/计划画在同一块看板上，并标出两者脱节的地方。

侧边栏面板有三个 Tab：

- **看板** — 按「提案 → 设计 → 计划 → 实现 → 校验 → 已验证 → 归档」排布的工作项。每张卡带 OpenSpec 与 Superpowers 两条进度、缺口标记、验证徽标（卡片在「已验证」栏时是「已验证 ×N」，最近一轮验证没通过是「上次验证未通过」，没有验证记录就两个都不戴），以及可以直接执行的动作。**「已验证」那一栏的卡片主按钮是「收尾」**，再验证一轮仍然可以，它留在「更多」里。**看板跟随左侧选中的项目**：侧边栏选中哪个工作空间，这里就显示哪个项目的工作项。**卡片的标题点开就是这个工作项的原文件**（在 Orca 的编辑器标签页里），标题下面还列着它其余的文件；项目在 Orca 里没有 workspace 时，标题就是普通文字，不做成按了没反应的链接。
- **全貌** — 两个框架各自的静态全貌：OpenSpec 的三个阶段、产物文件与「要不要写 proposal」的判定树，Superpowers 的十五个技能、产物与门禁，以及两边产物的对应关系。每个阶段下列出该框架自己的命令，可以直接 ▶ 执行。
- **项目** — Orca 知道的所有项目，**包括别的机器上的**，以及每个项目的扫描结果。还没采集的项目标着「需 agent 采集」。

插件只做两件事：读取工作区里的 OpenSpec 与 Superpowers 产物，然后调用这两个框架自己的命令（`openspec …` 或 Superpowers 技能）。它自己不往项目里写文件——它只发起动作，改状态的是这两个框架自己的命令。

## 验证轮次

计划文件末尾的「## 验证记录」一节里，**验证 agent 每跑完一轮验证就写一行**：

```markdown
## 验证记录

- 2026-11-27 · 通过 · pnpm tc
- 2026-11-27 · 未通过 · worker-refresh-project.test.ts flaky
```

看板从这一节数出轮次：结论只认「通过」或「未通过」，最近一轮通过、计划又全部勾完的工作项，从「校验」栏进到「已验证」栏，戴上「已验证 ×N」的徽标，主按钮变成「收尾」。没有这一节就没有轮次——**没有证据就不显示「已验证」**。

这一节是 agent 写的，插件一个字节也不写：它只读这一节，只发起动作。

## 远程项目

本机的产物由插件自己扫；别的机器上的产物由 agent 采集——插件的 host API 没有读文件的方法（连本地都没有），所以采集必须在那边跑。

刷新时插件在本机启动 agent，把要扫的项目清单和快照格式写进 `~/.orca/spec-board/scan-list.json`，让 agent 按清单逐个扫：本地项目直接读，别的机器上的项目用 `ssh` 去读（Windows 主机用 PowerShell）。快照写回本机的 `~/.orca/spec-board/board.json`，插件再把它和本地扫描合并。

清单里的 `host` 是 Orca 的主机 id（`local`、`ssh:<目标id>`、`runtime:<环境id>`），不是 ssh 名字，agent 先向 Orca 问出那台机器的 ssh 名字再连。

刷新一定在本机跑：快照只有写在本机，插件才读得到它。

## 刷新

「项目」Tab 上方的按钮刷新整个看板：一次扫完所有项目。

每一张项目卡片上还有自己的刷新按钮，只重新采集那一个项目：

- **本机项目**：插件自己扫一遍，几秒就好，不开终端也不启 agent。
- **别的机器上的项目**：插件在本机启动 agent，清单里只有这一个项目，扫到的结果写进这个项目自己的文件 `~/.orca/spec-board/project-<hash>.json`；插件再把这个文件并进 `board.json`。别的项目一个字节都不动。

单项目刷新扫到的文件比整块快照旧时会被丢掉：整体刷新可能落在单项目刷新之后，旧的数据不能盖掉新的。

## 开发

```sh
orca plugin validate .   # 校验清单
orca plugin test .      # 跑 src 下的测试
orca plugin dev watch . # 把这个文件夹加载进 Orca，改动自动重载
```
